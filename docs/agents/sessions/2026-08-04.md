# Session 2026-08-04 — account identity and honest financial actions

## Account-scoped first run

- The in-match tutorial was previously one browser-wide flag. It is now keyed by
  `Telegram.WebApp.initDataUnsafe.user.id`.
- The player profile/progression store is scoped by the same Telegram id, so a
  second account on one device cannot inherit another account's completed
  onboarding, nickname, inventory or progress.
- The first Telegram account opening the account-aware release receives the old
  unscoped profile and tutorial flag once. The legacy keys are removed, allowing
  later accounts to start clean.
- Outside Telegram, local browser behavior stays unchanged. `?tour=1` continues
  to force the ten-step match tutorial for QA.

## Honest transport feedback

The WebSocket client already reconnected and resumed a room, but store actions
often ignored `send() === false` and immediately returned success. The UI could
therefore say an asset was bought, a deal accepted or a reaction sent when no
command left the phone.

Boolean economy operations now propagate transport failure. Personal offers,
table help, futures, incoming deals and card submission no longer claim success
on a dead socket. The main decision CTA blocks during reconnect, asks the player
to repeat the decision, and triggers an immediate reconnect. Stale financial
commands are intentionally not queued: replaying a purchase or sale after the
state changes would create duplicate or outdated decisions.

## Browser-discovered engine/UI mismatch

The 402×874 rendered market enabled Coffee at `$1,000`, but clicking it produced
`Недостаточно наличных` while the player had `$2,000+`. The real reason was a
canonical payload rejection: the registry requires upkeep `$10`, `$20` and `$50`
for Coffee, Kiosk and Studio, while the market omitted upkeep and sent zero.

The market now sends the complete canonical payload. Browser replay proved:

- Coffee purchase reduced cash by `$1,000`;
- the asset appeared in the profile ledger;
- passive income increased by `$200` and upkeep by `$10`;
- the market displays asset flow as `+$190/мес` with the `+$200 −$10`
  breakdown;
- sale review showed `+$720` cash and `−$190/мес` asset flow.

## Process observations for Studio

- Start UI audits from a real economic path (`visible price → command payload →
  registry validation → state delta → feedback`). Source-level agreement on names
  alone did not catch the upkeep mismatch.
- Do not add a generic offline command queue for financial actions. Reconnect the
  room and make the user reconfirm against the restored state.
- Keep one scoped accessibility snapshot per state and query exact controls after
  that. Repeated full dumps and complete build asset manifests are the largest
  avoidable context costs in this workflow.
- Separate stable product rules in Second Brain from chronological evidence in
  session logs; this keeps future agents from rereading the entire history.
