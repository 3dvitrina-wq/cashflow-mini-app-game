# LOCAL_PLAYTEST_GUIDE.md — Локальный тестовый матч DYOR

**Назначение:** Пошаговая инструкция для запуска локального тестового матча на 2+ игроков с ноутбука на одной Wi-Fi.

---

## ПРЕДУСЛОВИЯ

### Версия Node
- **Требование:** Node >=20
- **Проверка:** `node --version` (если <20, установи из https://nodejs.org/)

### npm install
```bash
# В корне проекта
npm install
```

---

## ПОШАГОВЫЙ ЗАПУСК

### Шаг 1: Узнай локальный IP ноутбука

**macOS / Linux:**
```bash
ipconfig getifaddr en0  # Wi-Fi
# Или через ifconfig | grep "inet " (не localhost)
```

**Windows:**
```cmd
ipconfig
# Найди IPv4 Address из Wi-Fi адаптера (обычно 192.168.x.x или 10.0.x.x)
```

**Результат:** например `192.168.1.50` — подставь в следующих шагах как `<LAPTOP_IP>`

---

### Шаг 2: Запусти сервер и фронтенд из корня

**Вариант А: Оба вместе (рекомендуется для первого теста)**
```bash
npm run dev
```

Это запустит через `concurrently`:
- **Server:** HTTP на `http://0.0.0.0:3001`, WebSocket на `ws://0.0.0.0:3002`
- **Web:** Vite на `http://0.0.0.0:5173`

В консоли увидишь:
```
[server] HTTP listening on http://0.0.0.0:3001
[server] WebSocket listening on ws://0.0.0.0:3002
VITE v5.3.1 ready in XYZ ms
➜  Local:   http://localhost:5173/
➜  press h to show help
```

**Вариант Б: Отдельно (для диагностики)**
```bash
# Терминал 1
npm run server
# Терминал 2
npm run web
```

---

### Шаг 3: Открой Web на первом игроке

На **первом устройстве** (может быть ноутбук, тестовое окно браузера или реальный телефон на Wi-Fi):

```
http://<LAPTOP_IP>:5173
```

Примеры:
- Если IP `192.168.1.50`: `http://192.168.1.50:5173`
- Если тестируешь локально на ноутбуке: `http://localhost:5173`

**Ожидаемый результат:** Загрузится фронтенд, увидишь экран создания комнаты или лобби.

---

### Шаг 4: Создай комнату

На экране лобби:
1. **Выбери персонажа** (шесть вариантов: hustler, trader, operator, nomad, creator, office)
2. **Нажми "Создать комнату"** (или аналог на экране)
3. **Получишь код комнаты** (например, `A7K2P`)

Запиши этот код — он нужен остальным игрокам.

---

### Шаг 5: Присоединись вторым игроком (+ тригером тестовую игру)

Открой **второе окно браузера** или **второе устройство** на той же Wi-Fi:

```
http://<LAPTOP_IP>:5173
```

**Присоединись к комнате:**
1. Выбери персонажа
2. Введи код комнаты из шага 4 (или скопируй сгенерированный URL, если доступен)
3. Нажми "Присоединиться"

На первом игроке появится уведомление о присоединении второго.

---

### Шаг 6: Запусти матч

Когда 2+ игроков в комнате:
1. На экране лобби нажми **"Начать матч"** (кнопка активируется при 2+ игроках)
2. Оба игрока перейдут на экран игры

**Ожидаемый результат:**
- Видны 2+ игроков в player strip (вверху)
- Host bubble показывает информацию раунда
- Card stage в центре (карта эффектов или событие)
- Dashboard внизу (кэш, активы, статусы)
- Action buttons (4 кнопки: например, play card, express interest, settle, pass)

## ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ

### v0 Прототип

1. **Mock Telegram Auth**
   - Все игроки авторизуются локально
   - Нет реального Telegram Mini App auth
   - Telegram Bot не подключён (apps/bot пока заглушка)

2. **In-Memory State**
   - Сервер хранит комнаты в памяти (new Map())
   - Перезагрузка сервера = потеря всех комнат
   - Нет Postgres / Drizzle / Redis

3. **No Bot Takeover**
   - Если игрок дисконнектится, его место не заполнится ботом автоматически
   - TODO: реализовать @150 мин одного раунда

4. **No Rive/Lottie Animations**
   - Character avatars = статичные PNG или ASCII
   - Мобильное UI работает, но без плавных переходов
   - Это нормально для прототипа

5. **No Sound / Haptics**
   - Никаких audio триггеров
   - Мобильная vibration не подключена
   - Host voice только текстовые bubble (template library, no LLM)

### Интернет-доступ

- **Только локальная Wi-Fi** — не работает через публичный интернет до Phase 4
- Телефоны и ноутбук должны быть в одной сети

## TROUBLESHOOTING

### "Cannot connect to server" (в браузере или консоли)

**Диагностика:**
1. Проверь, что `npm run dev` / `npm run server` не упал в консоли
2. Проверь IP: `ipconfig getifaddr en0` должен совпадать с тем, что вбил в браузер
3. Проверь порты: `npm run server` слушает на `:3001` (HTTP) и `:3002` (WebSocket)
4. Firewall: убедись, что macOS/Windows firewall не блокирует Node
   - **macOS:** System Preferences → Security → Allow Node in firewall

**Если не помогает:**
- Используй `http://localhost:5173` на том же ноутбуке (вместо IP)
- Если нужен реальный телефон: настрой локальный proxy или используй ngrok (не для MVP, только для debug)

### "Room not found" (после присоединения)

- Код комнаты чувствителен к регистру? Проверь CAPS / lowercase
- Комната была создана, но сервер перезагрузился — создай новую
- Если несколько серверов запущено (портконфликт) — убей старый процесс: `lsof -i :3001` → `kill -9 <PID>`

### WebSocket не коннектится, но HTTP работает

- Проверь, что `http://<IP>:3001/health` вернул `{"ok":true}`
- WebSocket слушает на порту `3002` — убедись, что он свободен: `lsof -i :3002`
- В браузере посмотри Network tab → WS connections

### Игра зависла после создания комнаты

- **Вероятная причина:** UI не интегрирована с engine (`store/index.ts` fallbacks срабатывают, но engineState не передаётся)
- **Временное решение:** Перезагрузи браузер, попробуй ещё раз
- **Правильное решение:** Убрать fallbacks и всегда использовать `engineState` (Phase 3 UI integration, планируется)

## РАСШИРЕННОЕ ТЕСТИРОВАНИЕ

### 3+ игроков (опционально)

Повтори шаги 5-6, но открой **третий и больше браузеров/телефонов** с тем же кодом комнаты. Максимум 6 игроков в комнате (ограничение в `rooms.ts`, `if (room.members.length >= 6) return null`).

### Single-Player (Если multiplayer падает)

Если WebSocket нестабильна:
1. Вернись на LobbyScreen
2. Нажми "Single-Player" или "Play vs Bots"
3. Выбери 3 бота для заполнения сидений
4. Локальный матч через engine (без сервера) будет работать

Это не требует WebSocket, только React store.

### Проверить детерминизм (для QA)

Если хочешь убедиться, что engine действительно детерминирован:
```bash
npm run sim  # Прогни 100 bot матчей
npm run audit  # Баланс-репорт (win rates, income variance)
```

## ПРИМЕЧАНИЯ

### Для оператора / продакта

- **Цель:** Убедиться, что 25–45 мин игровой цикл читаемо проходит на 2–6 игроков
- **Что смотреть:**
  - Пейсинг: не слишком быстро? Хватает времени на решения?
  - Баланс: кто выигрывает чаще? (Должны быть 3 разные стратегии с 18–32% win rate)
  - UI: кнопки в удобных местах? Сложно ли читать статусы других игроков?
  - Каких элементов не хватает для понимания?
- **Как собирать feedback:**
  - Вызови zoom, делись экраном, наблюдай за реакциями
  - Или проведи playtest на реальных телефонах на Wi-Fi

### Для инженера

- **Лог сервера:** вся информация о создании/присоединении к комнате, командах, стейт-апдейтах
- **Лог браузера:** Console tab в DevTools покажет WebSocket messages, store updates, ошибки UI
- **Дефолт порты:** если хочешь изменить (3001/3002/5173), переделай `apps/server/src/index.ts` + `vite.config.ts` + env vars
