# DIOR Club Network Lab

Статический стенд поднимает шесть независимых браузерных профилей. Каждый профиль
держит собственный WebSocket и отправляет команды только со своим `playerId`.
Комнаты, ходы, таймауты и bot takeover остаются в реальном `apps/server`.

## Запуск

Нужен Node.js 20+ и уже установленные зависимости репозитория.

Терминал 1, из корня репозитория:

```bash
npm run server
```

Это запускает `apps/server` на `http://127.0.0.1:3001` и WebSocket на
`ws://127.0.0.1:3001/ws`.

Терминал 2, из корня репозитория:

```bash
python3 -m http.server 4173 --directory tools/network-lab
```

Открыть:

```text
http://127.0.0.1:4173
```

REST и WebSocket адреса можно изменить в верхней панели до подключения.
Для проверки состава 2–6 можно подключать карточки по одной через **Connect**;
старт разрешён при двух и более подключённых профилях.

## BASIC: шесть личных карт без ожидания по очереди

1. Нажать **Создать комнату**, затем **Подключить всех**.
2. Убедиться, что все шесть карточек показывают `CONNECTED` только после
   подтверждения места сервером и один room code.
3. Оставить `Обычный · личные карты`, указать `maxRounds` и нажать **Старт матча**.
4. Убедиться, что у шести профилей разные личные карточки, а затем на каждой
   карточке отдельно нажать Option или Pass.
5. Проверить, что `intent принят` появляется только у конкретного профиля, а
   остальные могут отвечать параллельно. Раунд меняется после шести intent.
6. Повторно нажать команду того же профиля и проверить server error/журнал:
   стенд не подменяет `playerId`, сервер сам отклоняет повтор.
7. После очередного snapshot убедиться, что banner показывает `SYNC 6/6`.

Статусы сравнения snapshot:

- `WAIT` — хотя бы один подключённый и подтверждённый профиль ещё не получил snapshot;
- `STALE` — профили временно видят разные ревизии во время рассылки;
- `SYNC` — одна ревизия и одинаковый hash общей части state у всех профилей;
- `DIVERGENCE` — одна ревизия, но hash действительно различается.

В BASIC из сравнения исключены `currentCard`, `currentCardId`,
`personalCardIds` и личные предложения: эти поля обязаны различаться между
профилями и не являются рассинхронизацией.
Фактические `pendingIntents` также приватны: стенд сравнивает общий список тех,
кто уже зафиксировал решение, но не видит чужой выбор до расчёта месяца.

Отключённые и ещё не подтверждённые профили в сравнение не входят.

Snapshot сервера содержит `currentCard` с русским описанием и labels вариантов.
Это только копирайт для человека и стенда: валидность индекса, стоимость и эффекты
по-прежнему проверяет server authority. Auto использует три повторяемые персоны:
агрессивная берёт первый вариант, сбалансированная — второй доступный,
консервативная — последний. Это проверка разных decision paths, не balance oracle.
Если выбранный вариант сервер отклоняет (например, не хватает наличных), профиль
один раз отправляет безопасный Pass и не зацикливает прогон.

## PRO: общий финансовый стол

1. Для чистого матча перезагрузить стенд, создать новую комнату и подключить всех.
2. Выбрать `PRO · общий стол`, указать `maxRounds`, нажать **Старт матча**.
3. Убедиться, что все шесть профилей видят одну карточку, но отправляют решения
   из шести отдельных WebSocket.
4. Проверить доступность сделок и партнёрств только в PRO, а также одинаковый
   hash snapshot после завершения каждого окна решений.

## Disconnect, takeover и reclaim

1. Во время хода конкретного профиля нажать на его карточке **Disconnect**.
2. Проверить `player_disconnected` у оставшихся клиентов и продолжение игры после
   server-side bot takeover.
3. Нажать **Reconnect** на отключённой карточке.
4. Проверить сообщение `reconnected`, новый snapshot и возврат управления месту.

Для проверки intent timeout оставить один профиль без команды на 25 секунд:
сервер должен поставить ему пас, завершить месяц и разослать новый state.

Кнопка **Auto: до конца** отправляет команды от всех шести собственных сокетов.
**Пауза** останавливает прогон. Предохранитель срабатывает после 2000 отправок или
10 минут. Checkbox **Auto** включает автоматизацию только выбранного профиля.

## Проверки

Из корня репозитория:

```bash
node --check tools/network-lab/app.js
node tools/network-lab/smoke.mjs
node tools/network-lab/reconnect-smoke.mjs
npm run typecheck:server
```

Smoke не требует новых npm-зависимостей и проверяет шесть профилей, отдельное
создание WebSocket, controls, hash и отсутствие клиентской room/engine authority.
`reconnect-smoke.mjs` проверяет повторную привязку того же мобильного сеанса к
комнате, серверную паузу обучения и адресную реакцию. Для другого стенда задайте
`DYOR_TEST_HTTP_URL` и `DYOR_TEST_WS_URL`.
